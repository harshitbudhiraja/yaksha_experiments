\section{Multi-Turn Instruction Following}
\label{app:multiturn-if}

We measure whether models keep satisfying instructions as a coding
conversation adds them one turn at a time, using
CodeIF-Bench~\citep{wang2025codeif}. Every instruction in the benchmark comes
with executable unit tests, so compliance is decided by running code, not by
an LLM judge.

\subsection{Experimental Setup}
\label{app:multiturn-if-setup}

\paragraph{Data.}
We use the function-level split, which is derived from MBPP. Each task has a
short specification with base assertions, plus six requirement types, each
with its own unit tests: \emph{Input--Output Conditions}, \emph{Exception
Handling}, \emph{Edge Case Handling}, \emph{Annotation Coverage}, \emph{Code
Complexity}, and \emph{Code Standard} (PEP~8). We exclude \emph{Functionality
Extension} because it changes the function signature, which invalidates the
base assertions. The released file \texttt{L\_1\_part\_2.jsonl} (20 tasks)
uses the repository-level schema: its tests are \texttt{pytest} node
identifiers, which pass vacuously when executed as Python. We therefore
evaluate on the remaining \textbf{50 function-level tasks}.

\paragraph{Protocols.}
\emph{Static}: requirements are issued one per turn in the benchmark's fixed
order, with no feedback and no retries. This isolates retention from repair.
\emph{Dynamic}: each round issues the first requirement that the current code
fails. If the model fails it, one feedback turn quotes the failing check; if
it fails again, the requirement is dropped. After every assistant turn, we run the unit
tests for \emph{all} of the task's requirements against the current code.

\paragraph{Metrics.}
Let $S_t$ be the instructions issued up to turn $t$ (the base specification
counts as one), and let $P_t$ be the earlier instructions the model had already
satisfied. \textbf{IA} is 1 if the instruction issued at turn $t$ passes all its
tests. \textbf{CA} is the fraction of $S_t$ that passes at turn $t$.
\textbf{IFR} is the fraction of $P_t$ that fails at turn $t$. IA, CA and IFR are
averaged over turns. \textbf{CIF} is the number of the task's seven
instructions that the final code satisfies. We also report \emph{base
retention}, the fraction of dialogues whose final code still passes the
original MBPP assertions, and the \emph{unprompted pass rate}, the fraction of
instructions that already pass at turn~1, before they are issued. IA is
comparable only within a protocol, because the dynamic protocol issues only
instructions that the current code fails.

\paragraph{Models and decoding.}
We evaluate Llama-3.1-8B-Instruct, Qwen2.5-Coder-14B-Instruct, GPT-OSS-20B,
Qwen3-Coder-30B-A3B-Instruct, and Gemma-4-31B-it. Each model is served locally
with vLLM at native precision on a single NVIDIA A100-80GB (tensor
parallelism 1, maximum context 16{,}384 tokens, seed 42). We decode greedily
(temperature 0) with up to 2{,}048 new tokens per turn. For GPT-OSS-20B we set
\texttt{reasoning\_effort=low}. No system prompt is used.

\paragraph{Execution.}
Candidate code runs in a temporary working directory with a memory cap. Each
unit-test snippet runs in its own subprocess with a 15\,s timeout, so one crash
does not fail the other snippets of the same requirement. If a turn contains no
runnable code, the previous turn's code is kept. We reimplemented the reference
harness because the released scripts hardcode hosted-API credentials. On the
same 50 tasks our harness agrees closely with the reference one (static IA:
Gemma-4-31B 0.773 vs.\ 0.770; Qwen2.5-Coder-14B 0.624 vs.\ 0.655).

Table~\ref{tab:mtif-main} reports the results. Gemma-4-31B-it has the highest
IA and CA under both protocols, and GPT-OSS-20B is close behind. The four
stronger models rarely break instructions they have already satisfied
(IFR 0.02--0.05); they differ mainly in whether they satisfy the \emph{new}
instruction (IA). Llama-3.1-8B-Instruct is the exception. Its static IA
(0.572) is only 5 points below Qwen2.5-Coder-14B's, but its IFR is
$4.5\times$ higher (0.165 vs.\ 0.037). In 76\% of its static dialogues, the
final function no longer passes the original specification. It meets the
current instruction by undoing earlier ones, which per-turn IA alone does not
show. Between 45\% and 58\% of instructions pass before they are issued, mainly
\emph{Exception Handling} and \emph{Code Complexity}, some of whose tests pass
vacuously. CA and CIF should therefore be read relative to the unprompted
rate.
